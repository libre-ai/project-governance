# Libre-AI Forge — Construction by observable outcomes

Status: execution direction accepted; implementation and qualification pending per capability.

## A — Reconcile authorities and retain sources

Record current refs, work in progress, shared contracts and owners. Restore preservation copies and reconcile existing recovery branches. Admit only reviewed content; documentary availability is not application availability.

## B — Exercise a complete bounded mission

Specify TaskContract, a revision-bound RepositoryManifest and an ExecutionProtocol candidate. Connect one real executor early, with explicit permissions and independent acceptance. Produce a candidate, integrate through the repository's checks, distribute through an authorized channel and verify the actual user journey.

## C — Prove continuity under failure

Interrupt execution before, during and after an external effect. Fence expired attempts, observe effects, refuse unsafe retries and resume from compatible state. Exercise cancellation, invalidation, contradictory evidence and unavailable dependencies.

## D — Prove changes across products

Evolve a shared contract and its consumers with an explicit impact set. Qualify migrations, protected behaviors, authority and product-specific acceptance. Preserve independent data ownership and releases.

## E — Prove executor and environment portability

Run the same task contract using a second admitted executor. Distinguish task/artifact recovery from internal checkpoint compatibility. Name unsupported capabilities and keep the configured provider explicit.

## F — Qualify platforms and deployment profiles

Verify actual installation or web availability and the admitted user journeys. Native system controls, shared Rust behavior, browser conventions and offline profiles each need their own evidence. A build alone does not establish these properties.

## G — Distribute reusable capabilities and learning

Publish only authorized code, sanitized knowledge, contracts and reproducible evidence. Confirm an independent user can reconstruct and use the result. Keep failed hypotheses and limits inspectable.

## Continuous controls

Context growth must answer an unknown or acceptance failure. Convergence alerts never weaken acceptance. Read models expose decisions and state without becoming authoritative. API contracts, E2E, coverage, review and post-release smoke checks apply to the selected behavior, revision and profile.

No platform-wide claim follows from a single successful mission. Repository count, agent count and a green launcher are not completion criteria.
