# Libre AI Project Governance

## Intended use

Make the portfolio understandable and its decisions inspectable: what each repository is for, which capabilities are active, which remain future scope and which evidence supports those statements. Governance owns portfolio doctrine, decision records and navigation rules; Contracts owns canonical exchange definitions.

## Existing candidates and limits

Existing sources contain doctrine, decision records, catalogs and verification tools, including knowledge-graph projection candidates. Their presence does not admit every tool or product. The refoundation retains twenty repositories with fresh Git history and selective capability activation. Its delivery promise is a clear, navigable portfolio, without requiring one complete application journey.

## Proposed boundaries

Record a repository’s role, admitted scope, limits and evidence explicitly. Distinguish an editorial description, a reviewed source, a composed tree and authorization to publish. Historical sources are evidence for review, not the default agent context or an instruction to retain their full history. Deletion requires a separately verified exact scope and the planned destructive confirmation.

## Activation criteria

Review bilingual facts and canonical navigation, verify exact source provenance and rights, and check each proposed target against its admitted scope. Qualify a selected governance tool with its own inputs, consumer and refusal evidence. Documentary repository existence and bounded tool admission do not require completion of Missions or other future products.
