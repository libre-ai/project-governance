# Banc d'essai des mécanismes de dépendance (design §5.2.6) — exécuté 2026-07-28/29

Reproductible : `bun verification/dependency-bench/run.ts` régénère les fixtures dans un
répertoire temporaire et rejoue les cas exerçables hors ligne (2, 3, 4) ; `--online` rejoue
en plus le cas 5 (git-dep GitHub réelle + cargo-deny). Le premier passage (2026-07-28)
avait ses fixtures hors dépôt — défaut de reproductibilité relevé en revue K4 (CARDS-06)
et fermé par ce script le 2026-07-29.

Incident tracé (K4 re-passe, BENCH-01) : la première version versionnée du script portait un
`rev` fabriqué pour le cas 5 (préfixe court `5c1bf05` complété par un remplissage au lieu du
SHA réel) — le rejeu `--online` échouait donc en résolution, sans exercer ni la preuve ni la
contre-preuve. Corrigé par la mesure : `rev = 5c1bf0523b8e81476096bc4a8fe888b1758d72f4`
(vérifié `git cat-file -t` → commit), rejeu `--online` du 2026-07-29 → cas 5 **PASS**
(`sources ok` exit 0 avec `[sources.allow-org]`, exit 8 sans — contre-preuve), résumé
4 pass / 0 fail / 0 skip / 1 deferred. Les codes 0/8 enregistrés le 2026-07-28 étaient
authentiques ; seul le SHA recopié dans le script ne l'était pas.

Bonus prouvé (cas 5) : **cargo résout un crate membre d'un workspace via git-dep** (le repo hub entier comme source, crate ciblé par nom) — utile pendant la transition, avant l'éclatement des workspaces Rust.

Findings de banc pour le plan de migration (3.3/3.4) :

1. ~~Le SHA-pin Bun sur transport GitHub restait le seul mécanisme non exercé localement.~~ **Soldé le 2026-07-29, deux preuves indépendantes** : (a) banc direct — `bun install` de `github:libre-ai/governance#b8b741c0…` installe le contenu au SHA épinglé (bun.lock porte le SHA complet, transport tarball codeload), contre-preuve versionnée `run.ts --online` cas 1 : `#deadbeef…` → échec « failed to resolve » (K4 CLOSE33-01) ; la moitié positive est portée par `contracts/bun.lock` (SHA complet + empreinte d'intégrité sha512, re-vérifiés à chaque `bun install --frozen-lockfile` de sa CI — plus fort qu'une fixture). Rejeu `--online` du banc complet : **5 pass / 0 fail / 0 skip / 0 deferred** ; (b) usage en production — `contracts` consomme `github:libre-ai/governance#6eae09b5…` pour son floor et ses scanners, **vert en CI réelle** (2/2 @ `6409226`, relevé K4 AUTH-R2-02), avant tout retrait de chemin (préalable §5.4 acquis).
2. Bun n'exécute aucun lifecycle de la git-dep (confirmé par construction — aucun `dist/` produit) : la condition d'exports `bun` est la seule servie, conformément au design §5.2.2.
3. `uploadpack.allowAnySHA1InWant` n'aide pas les transports `file://` — les fixtures de banc futures devront utiliser des refs, ou GitHub. Les fixtures sont désormais régénérées par `verification/dependency-bench/run.ts` (aucune fixture persistée hors dépôt).
