# Distribution

Templates, projections de repositories, documentation, knowledge packs, SDK et supports d’acculturation.

Le sous-dossier `feeds/` contient les projections générées de l'évidence (changelog Markdown, feed JSON, feed Atom), produites par `distribution/build-feeds.ts` — jamais éditées à la main ; leur fraîcheur est garantie par le workflow `feeds-freshness`.

Le sous-dossier `vision/` contient la page vision (ADR-0064 D6) : `index.html` est généré par `distribution/build-vision.ts` depuis la carte des briques (`ecosystem/briques/`), et ne s'édite jamais à la main ; `vision.css` est écrit à la main. La page ne porte ni script ni style en ligne. Le générateur lance le gate de la carte et n'écrit rien si la carte a une violation. Le workflow `brick-map` régénère la page et échoue sur une dérive. Régénérer : `bun run build:vision`. Aucun site ne sert cette page : c'est un fichier de ce dépôt.

Le fichier `index/products-with-code.v1.json` est la liste des produits dont du code existe, source du marqueur « Du code existe » du site (choix du propriétaire du 2026-11-15, forme « Produit + chemin vérifié » du 2026-11-16). Un produit y figure quand la fiche de projet du dépôt que sa fiche produit nomme dans `depot` le déclare dans `products`, et que la branche servie de ce dépôt suit le chemin déclaré. Il est généré par `distribution/build-products-with-code.ts` depuis l'évaluation même de `ecosystem/check-fleet-versions.ts`, et ne s'édite jamais à la main. Le générateur n'écrit rien si ce contrôle a une violation ; un contrôle vert sans aucun produit déclaré écrit une liste vide. Contrat du fichier : `ecosystem/schemas/products-with-code.v1.schema.json`. Le fichier ne porte ni horodatage ni commit des dépôts lus : il ne change que lorsqu'une fiche déclare, déplace ou retire un produit, ou qu'un chemin cesse d'être suivi. Le workflow `products-with-code` le régénère et échoue sur une dérive, à chaque push, sur chaque pull request et chaque semaine, puisque la dérive peut venir d'un autre dépôt ; deux échecs planifiés consécutifs ouvrent un ticket de gouvernance. Régénérer : `bun run build:products-with-code`. Le site en lit une copie épinglée.
